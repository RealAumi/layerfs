## Limits on reading these numbers

- **Single samples under load.** The host was loaded (1-minute load 9–10)
  and another owner's container was running. The first pair's eleven
  LayerFS rows, run 5 minutes earlier on the same binaries, differ from
  these by up to 57 %: `stat 1000 files` was 832,173,084 ns there and
  1,306,344,876 ns here. That first pair ran its LayerFS arm as root, so it
  isn't a like-for-like repeat. Treat each row as one observation; a single
  pair cannot support a precise ratio.
- **Different FUSE and container profiles, by design.** Computer has a
  larger `max_read`, auto_cache, `relatime` and a privileged container.
  LayerFS has a smaller `max_read`, no writeback, `noatime` and the SDK's
  narrower container. The comparison is of each system as deployed, not of
  identical kernel settings.
- **Warm-state rows.** The three own-write warm rows measure warm-state
  behaviour, not cold reads.
- **Scope.** The rows exercise zero-filled inputs, resident FUSE operations
  and native arm64 in Docker Desktop on macOS. A native x86-64 Linux host
  remains the route to a qualifying pair.
