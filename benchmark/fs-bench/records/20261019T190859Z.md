## Why the git row failed

A separate diagnostic was run on a fresh holder mount and is not a sample.
Its log is `diagnostic-git-ownership-holder.log`. Running as root,
`git init` succeeded. `git add -A` and `git commit` then each exited 128
with `fatal: detected dubious ownership in repository at '/workspaces/1/g'`.

Every inode on the mount, including ones root had just created, is
presented as uid 501, gid 20. That is the documented contract: "projected
inode ownership is the command identity"
([native mount session](../../../core/docs/architecture/76-native-mount-session.md)).
Git 2.39.5 refuses a repository whose owner is not the current user, and
`run.sh` runs the script through `docker exec` as root. In the same
diagnostic, as uid 501 (the Sandbox command identity), the same
init/add/commit of 100 files succeeded.

The failure therefore comes from the collector's user choice, not from a
LayerFS filesystem error. It still stands as this pair's recorded outcome.
